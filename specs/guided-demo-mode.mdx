**Version 2 · 29 October 2026 · supersedes v1 (30 October 2026, @Marcus)**

Guided Demo Mode lets a founder run the full Shortlistr product story in the production app, using fixed sample data, by clicking **Next**. It serves the Startmate demo video, investor meetings and customer demos.

<Warning>
  **Why this version exists.** v1 described screens, labels and data the app doesn't have, and the build followed v1 rather than the app. The current build (`/demo`) renders 14 purpose-built mock components from `src/demo/demoSeed.js`. None of them is a production screen, so the demo shows an app that doesn't exist. v2 rewrites every screen against the real routes, tabs, components and records, and lists what has to change in the build.
</Warning>

## Purpose and scope

There's one demo, built into the product, that tells the same story every time. You follow one candidate's application from the candidate's side through to the employer's and agency's dashboards.

### Who uses it

- **Founders:** the Startmate video and Loom, investor meetings, Demo Day
- **Customer demos:** prospective employers, agencies and Lab partners, run live by a founder on a call
- **No self-serve for now:** founders run every demo

### What it must do

- Move through a fixed sequence of **real production screens** with one **Next** button, plus **Back**
- Show fully populated sample data on every screen, with no empty states, no "Insufficient data", no "Building signal" and no locked or **Gated** panels
- Highlight the one thing that matters on each screen with a callout
- Offer short tracks for a candidate, employer or agency audience
- Never touch real user data, send a notification or email, spend AI credits or call an AI model

### Out of scope for v1

- Editing demo data in the app (data is seeded and reset from a fixed set)
- Personalising the demo with a prospect's real company name or logo
- Live AI interactions during the demo (outputs are pre-generated)
- The public self-serve version on the marketing site
- **Recruiter-level reporting** (employer and agency **Team Performance**). It returns to the demo once the page ships.
- **Market insights** (salary expectations, benefits peers offer, applicant quality). It returns to the demo once the feature ships.

This builds on the Lab decision to show seeded data through a Live/Demo toggle in the live environment, not a separate sandbox site.

## How it works

### Starting a demo

- **Start demo** in the account menu (already built in `NavAuthControl`) opens `/demo`. Only platform admins (`role: admin`) can see or open it.
- The start screen picks a track and takes an optional **Presenting to** name, which only changes the welcome line (for example, "Welcome, Startmate"). This is already built.
- Starting a demo sets Demo mode on, then navigates to the **real route** for screen 1 of the track. Each screen loads the real page as the right demo persona. Your own account and data are untouched.

### Tracks

| Track | Screens | Length | Use for |
|---|---|---|---|
| Full story | 1–15 | About 2½ minutes | Investors, Startmate, Demo Day |
| Candidate | 1–9, 15 | About 1½ minutes | Candidate partners, launch content |
| Employer | 1, 6, 7, 8, 10–12, 14, 15 | About 2 minutes | Prospective employers, Lab partners |
| Agency | 1, 6, 8, 13, 14, 15 | About 1½ minutes | Prospective agencies |

### Demo bar

The demo bar sits fixed at the bottom of every screen, above the hub's own chrome. This is already built in `DemoBar`.

- **Back** and **Next** buttons, plus the ← and → keys
- Progress, for example "5 of 15 · Interview Coach"
- **Notes** (N key) toggles a presenter panel with the talking point. It's hidden by default and never shows in recordings unless turned on.
- **Restart** (R key) and **Exit demo** (Esc)
- A persistent **DEMO MODE** pill, so a presenter never mistakes it for live data

### Callouts

Each screen opens with one callout pointing at the feature that matters. It fades after three seconds or on the first click, and callouts can be switched off for a clean recording. Callouts must anchor to the **real element** on the production screen (via a `data-demo-anchor` attribute), not to mock markup.

### Navigation inside a screen

You can scroll, hover and switch tabs within a screen. Any action that would change data, send a message or start a session is blocked with a small "Disabled in demo" tooltip. Where the story needs an in-app step (opening a card, switching a tab, opening a modal), the demo performs it on **Next**.

### Screen notes

#### Screen 2: extension

- The side panel is titled **Application Tracker** and saves with **Save to Application Tracker**. A save creates a `JobTrayItem` and an `Application` at stage **Saved** through `saveFromExtension`.
- The extension only injects its job-capture script on Seek, LinkedIn and Indeed. shortlistr.io only gets the sign-in script. A job ad page hosted on shortlistr.io needs a site adapter and a new extension release through Chrome Web Store review, so plan for that lead time.
- The extension signs in by reading the access token from any open Shortlistr tab. In a demo, that tab belongs to the founder, so a clip would land in the founder's own tracker, not Priya's. The extension needs a demo sign-in path, or this screen uses the recorded fallback.
- If the extension isn't installed or signed in, screen 2 plays a short recorded clip and the demo carries on.

#### Screen 3: tracker

The tracker that ships is `ApplicationsTab` › `KanbanBoard` › `ApplicationCard`. `KanbanCard`, `KanbanColumn.jsx`, `KanbanDetailPanel` and `InactivityPrompt` are orphaned files that nothing imports, so don't build against them.

**Step 1, the board:**

- An **Active** / **All** toggle, "N active", **Add Application**, and "Archived (post-review): N" above the board. **Active** hides every terminal stage (Hired, Withdrew, Unsuccessful, Ghosted).
- Columns of 240px: Saved, Applied, Initial Screen, Interviewing, Assessment, Final Round, Offer, Hired ✓, Archived. Each column header has a count and a **+**. Each column ends with **Add Application**, and Saved also shows "Save jobs via Chrome Extension". An empty column shows "Drop here".
- Each collapsed card shows the company logo, job title, company name and a chevron. Below that are a **Direct** or **Agency** pill, the column pill, and any of **✓ Reviewed**, **Review Pending**, **Silent Rejection Risk** or **Interview scheduled**, then a "N days ago · date" footer.
- At 1280×720 with the hub sidebar, only about four columns fit. The board scrolls sideways, so the demo must scroll it to keep the Demo Inc card in view.

**Step 2, the opened card.** Clicking a card opens a centred **Application Details** modal, not an inline expand:

- **Header:** a 48px logo, job title, company, a matched-company link, Date Created, a **Current Stage** select, and the employer's **Silent Rejection Risk** badge
- **Nudge banner**, from 14 days in stage
- **Tabs:** **Overview**, **Interview Brief**, **Review**, **Journey**, **Documents**, **Notes** and **Follow-up**
- **Overview fields:** Hiring Party Type, Applied Via, Company Website, Company, Recruiter Name, Recruiter Email, Location, Industry, Salary Range, Salary Disclosed At, Work Model, WFH Days Per Week, Employment Type, the job ad link, Benefits on Offer, Other Benefits, Pension / Superannuation, Leave and WFH Confirmed
- **Footer:** **Delete** and **Save Changes**, both disabled in Demo mode

Seed every Overview field on the Demo Inc card, so the modal shows a complete application with no blanks. The **Review** tab won't open a review until **Applied Via** and the recruiter details are filled, so screen 8 depends on this too.

#### Screen 4: Job Match

The match must not exist on screen until **Run match** is clicked, so screen 4 has two steps:

1. **Input view.** This is what **New match** (or **Run a match** on the empty state) opens. It has Job title, Company, "Resume for this match" (Priya's Base resume), Job ad text (the clipped Demo Inc ad), "This role is through a recruiting agency" (unticked) and "What matters more in this search?" (**Balanced**). The callout points at **Run match**.
2. **Next clicks Run match.** In Demo mode this calls no backend function. It shows the real analysing state for about a second, then opens the results view from the stored `JobMatchSession`.

The button in the app reads **Run match**. If you want it to read **Run Job Match**, that's a copy change to the production screen, not a demo setting.

The badge is derived, not stored. **Strong target** only shows when the overall match is 80 or more and no **required** requirement is classified as **Required gap** or **Not shown**. Seed Priya's gaps (for example, "marketplace pricing experience") as **preferred** requirements classified **Transferable**. Otherwise the badge drops to **Selective target** or **Validate first**.

#### Screen 5: coaching

Use the real Interview Coach tab (`HubCoachView`), not the post-call debrief overlay.

**Step 1, the coach page:**

- **Header:** "Practise with Interview Coach" and "Build an interview around the role, level and stage you're preparing for."
- **Left: the setup card (`Jen3SetupCard`).** Opening it with `application_id` links it to the Demo Inc application, which hides the General Practice / Targeted Interview choice.
  - **01 What are you preparing for?** Role title "Senior Product Manager", Seniority "Senior"
  - **02 What stage are you preparing for?** Interview stage **Final Round** ("Executive or cross-functional panel")
  - **03 How do you want to practise?** **Coach Mode** and **Interview Mode** cards with **Coach Mode** selected, then Session depth **Quick**, **Standard** or **Deep** with **Standard** selected ("~15 min · 5–6 questions")
  - **Summary:** "Jen's ready to build your interview", chips for each choice, "N sessions remaining this month", the transcription consent notice, and the start button, disabled in Demo mode
- **Right:** the Tip card ("Find a quiet space and allow microphone access…"), then **Recent sessions · 3 total**. Each session row shows a score tile out of 100, "role · company", the date, a stage pill and a one-line summary.

**Step 2, the session detail.** Next opens the top session (Demo Inc · Senior Product Manager · Final Round) in `CoachingFeedbackModal`:

- **Header:** the score badge (**Strong**, **Solid**, **Developing** or **Needs Work** with the score) and "N min session"
- **Sections:** **✦ Strengths** (`coaching_outcomes`), **Areas to Improve** (`recommended_next_steps`), **Coach Note** (`ai_feedback_summary`), **Dimension Scores** and **Topics Covered**, plus a **Full Transcript** toggle
- **Dimension Scores** are clarity, structure, confidence and relevance as percentages, from `ai_feedback_breakdown`

Seed 3 completed `CoachingSession` records with every one of those fields, so no section is missing. No live session starts, so nothing calls ElevenLabs. Drop the 10-second audio clip unless it's played from a stored file.

#### Screen 7: silence

The thresholds run off days in the current stage (`last_stage_change_at`):

| Days in stage | Collapsed card on the board | Banner in the opened card |
|---|---|---|
| 14–19 | No pill | **STALLED — FOLLOW UP · N DAYS**, with **Draft Follow-up** and **Update Status** |
| 20–29 | **Silent Rejection Risk** pill | **SILENT REJECTION RISK · N DAYS**, with the same buttons |
| 30+ | No pill (see [defects](#production-defects-found-during-the-audit)) | **LIKELY SILENT REJECTION · N DAYS**, "Silent rejection is highly likely…", plus **Mark as Ghosted** |

Open the Demo Inc card straight into the modal with `/hub?tab=tracker&app=<id>`, so the board's missing pill doesn't matter on this screen. **Mark as Ghosted** calls `confirmGhosted`. In Demo mode it must write nothing, show **✓ Ghosted** in the banner, and switch to the **Review** tab for screen 8.

#### Screen 9: trust explainer

The candidate never sees a check list in the real app, so this card is demo-only and must be labelled as an explainer, not a product screen. List only steps the pipeline actually runs:

1. **Verified account.** `createReview` applies the email-verification gate.
2. **Duplicate check.** `checkDuplicateReview`.
3. **Moderation and integrity.** `moderateReview` runs the Review Moderation Agent and the Review Integrity Agent in parallel.
4. **Hard rules.** Raw email addresses, phone numbers, hate speech and self-harm signals are caught before publication.
5. **Audit and escalation.** Every decision goes to `ModerationAuditLog`. Anything unresolved becomes a `ComplianceCase`.

Don't claim "legal and defamation" checks unless the moderation prompt is confirmed to run them.

#### Screen 10: employer overview

- When the SRRS gate is met, the ring shows the **Silent Rejection Risk Score** (27 · Moderate for Helply) and hides the "% rejection rate" line. Show the 14.3% SRR on screen 11 instead.
- **Benchmark** needs the **Pro** tier (`growth`). **Silent Rejection** and **Funnel** need **Plus** (`reputation`). Seed Demo Inc on **Pro** so nothing renders locked. The talking point still quotes the EmployerPlus entry price.
- The **AI credits** counter on this screen must show a fixed balance and never decrement.

#### Screen 12: respond

Only the **owner** and **admin** roles can respond to reviews, so Sam Lee must be one of those. Responses must be 30–1,500 characters and go through `moderateResponse`. Employers can flag a review (up to 3 flags every 30 days) but can't delete one.

## Technical and safety requirements

### Demo identity

The real screens can't show demo data today, because each one resolves "who am I" from the signed-in account:

- `CandidateHub` sends anyone without a complete `CandidateProfile` to profile setup, then loads `Application` by the signed-in user's id
- `EmployerHub` and `AgencyHub` find the company through `claimed_by_user_id`, `CompanyUser` or `org_id` on the signed-in user
- Child components (coach setup, Job Match, tracker cards) call `base44.auth.me()` again on their own

**Requirement:** add one effective-identity hook (for example `useEffectiveIdentity()`) that returns the demo persona's user, profile, company and org role while Demo mode is on, and the real user otherwise. Replace direct `base44.auth.me()` identity lookups on every screen in the demo path. Personas can't sign in directly. They're reachable only through Demo mode.

### Isolation

- Add an `is_demo` boolean to every entity the demo reads: `Company`, `CompanyUser`, `CandidateProfile`, `Application`, `ApplicationStageEvent`, `CandidateStageReview`, `ReviewResponse`, `SilentRejectionMetric`, `Partnership`, `JobMatchSession`, `CoachingSession`, `CareerMemory`, `MarketplaceProfile`, `AgencyEmployerLogoPermission` and `JobTrayItem`. Alternatively, confirm the platform's built-in `is_sample` flag can do this job.
- Demo records never appear outside Demo mode. Exclude them in search and the Directory, the Agency Marketplace, `CEIRollup`, `calculateCEIBenchmarks`, `calculateSilentRejection` and `refreshSilentRejection`, `computeMonthlyReviewAggregate`, `emitCanonicalEvent` and `exportCanonicalEventToBigQuery`, analytics and admin reporting.
- Demo Inc must not carry Helply's logo, website, LinkedIn, address, `company_id` or partnerships.

### Read-only

v1 said writes are "blocked at the backend function level". That isn't enough, because these screens also write straight to entities from the browser (for example `Application.update`, `ApplicationStageEvent.create` and `CandidateNotification.create` in the tracker, and the response in `RespondModal`).

- Block writes to `is_demo` records with entity RLS for every non-service caller, **and** short-circuit the frontend handlers in Demo mode so the presenter sees "Disabled in demo" instead of an error.
- Backend functions on the demo path must no-op in Demo mode: `generateCandidateInsights` (runs on Dashboard load), `refreshSilentRejection`, `confirmGhosted`, `createReview`, `postReviewProcessor`, `moderateResponse`, `matchCompanyToApplication`, `notifyRecruiterClaim`, `checkCoachingEligibility`, `prepareCoachingSession`, `generateInterviewBlueprint`, `assessJobMatchCapability`, `runWorkFitResearch` and the ElevenLabs session and token functions.
- Read-only functions may run against demo records: `getEmployerExploreData` and `getTeamMemberAvatars`.
- No emails, push or in-app notifications, weekly summaries or webhooks fire for demo records. No Stripe, Metronome, wallet or credit events, and no `AIUsageEvent` rows.
- **The one exception** is the screen 2 clip. It may create one `JobTrayItem` and one `Application` flagged `is_demo` for Priya, and they're removed on **Exit**, **Restart** or **Reset**.

### No live AI

- No calls to OpenAI, Anthropic, Gemini, ElevenLabs or fal.ai from Demo mode. Every AI output is read from stored demo records.
- Coaching plays from a stored session and, optionally, a stored audio file, never an ElevenLabs session.

### Reset and integrity

- A **Reset demo data** admin action and a nightly job restore every demo record from the seed file.
- The seed file is version-controlled in GitHub and kept plain JSON-shaped, so it moves to Xano unchanged after the backend migration. The existing `src/demo/demoSeed.js` becomes the source for seeding records, not the source the screens render from.

### Permissions

- Demo mode is available to accounts with the platform `admin` role. That's three accounts today (two belong to the same founder). There's no `demo_presenter` role, and no Lab partner, customer or self-serve access in v1.
- Starting, finishing and abandoning a demo is logged in `DemoRun` (who, when, track, screens reached). This is already built.

### Presentation quality

- Each screen loads in under 1 second, with demo records preloaded when the demo starts. The hubs' own "Loading your hub…" spinners must not show after 1 second.
- Works at 1280×720 and above, so it records cleanly for Loom and video. The hub sidebars hide at 1024px and below, so test at exactly 1280×720.
- The demo bar and callouts follow Design System v3.0, with Signal orange (`#F97316`) for highlights.
- The browser tab title and URL show "Demo", so a presenter can never mistake it for live data.

## Acceptance criteria

- A founder can start the Full story track and reach screen 15 using only **Next**, with no other clicks
- Each of the four tracks shows exactly the screens listed for it, in order
- Screens 2–8 and 10–14 render the production page at the listed route, with no demo-only copy of that page anywhere in the codebase
- On screen 3, the Demo Inc card opens into the **Application Details** modal with every Overview field filled
- On screen 4, no match score is visible until **Run match** is clicked
- On screen 5, the Interview Coach tab matches production (setup card, Tip, **Recent sessions**), and the session detail opens with every section filled
- **Back**, **Next**, ←, →, N, R and Esc work on every screen
- Every screen shows populated demo data, with no empty states, no locked or **Gated** panels, no "Insufficient data" or "Building signal", and no spinner after 1 second
- Demo Inc's numbers match wherever they appear (for example, CEI 69 on screens 6 and 10, and 27 reviews on screens 6 and 10)
- Helply's name, logo, website and address appear on no demo screen
- The extension clips the demo job into Priya's tracker (not the presenter's), and the clip is gone after **Exit**, **Restart** or **Reset**
- Trying to save, post, send, mark as ghosted or start a session in Demo mode shows "Disabled in demo" and changes no data, checked at both the RLS and function level
- No email, notification, credit deduction, `AIUsageEvent`, Stripe or Metronome event, and no AI provider call happens during a full run (checked in logs)
- Demo records don't appear in search, the Directory, the Marketplace, benchmarks, rollups, BigQuery or analytics outside Demo mode
- **Reset demo data** restores the seed exactly, and the nightly reset runs
- Only platform admin accounts can see or open Demo mode
- A full run records cleanly at 1280×720 with Notes hidden and callouts on or off
